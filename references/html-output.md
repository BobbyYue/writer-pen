# 文学HTML：作品先读，说明另放

本模块把Reader's Seat的离线HTML、排版、可访问性及实际页面检查移植为文学交付能力。
模板、脚本与检查器已随本包安装，不依赖Reader's Seat或html-report仍在本机，也不调用其四角色报告审读。
来源快照与适配范围在 [html-origin.json](html-origin.json)。不迁移业务文档的结论先行、章节结论、证据图表或事实保真规则。

## 格式与范围

- 完整作品、全篇改稿、多版本和改稿实录默认HTML。明确格式、已有目标与不落盘要求优先；
  只改题、单句修改、问答和轻量诊断不强制建文件。用户要把这些整理成文档时再用本模块。
- HTML默认保存在当前工作目录的`output/<作品名>/`，有指定路径则用指定路径。首次交付创建新文件，
  不覆盖原作；用户要求更新某个HTML时，先保存旧版，再原位更新该文件及关联说明。
- 默认无需服务器，直接本地打开。单篇只要题名和正文即可，不用封面、摘要、虚构读者评价或目录撑满页面。
- 多篇/多版本置于同一页，必要时加锚点目录；没有JavaScript也能读全篇。正文不能只存在于脚本变量、默认隐藏标签页或折叠区。
- 人物分析、修改理由、原文与痕迹按用户要求放正文之后，或在较宽屏幕的独立批注区；
  手机回到顺序阅读，不让批注把正文切成一段一卡。痕迹用`del`、`ins`及必要的移动说明，不能只用颜色表示删改。
- 不给小说强加配图、图表或教学引用；需要时用相关且有权使用的素材。虚构作品不逐句引用来源，
  方法说明或外部事实需要出处时，来源靠近相应说明，不能混进人物的叙述。

## 自包含与版式

默认模板是 [literary-template.html](../assets/html/literary-template.html)：单列正文、系统中文字体、
固定字号与受约束的行宽，无CDN、无外部字体、无脚本依赖，直接双击可读。
模板不是固定审美，按作品调整配色与气质，但保护叙述节奏和原来的分段。
不要为了“轻盈”缩字、为了手机屏幕拆段，或把含蓄结尾改成加粗金句。

- 普通正文默认18px、约42rem行宽，优先调边距与行宽；正文不低于14px，字号不随视口缩放。
  行距、段距是起点，不是每篇必须相同的文学尺度；诗行、片段与有意空白按实际作品保留。
- 文字和操作保持可辨的对比，链接/控件有键盘焦点；不用颜色作为唯一提示。
- 全局颜色和字体用CSS变量。长题名能换行，不出容器；正文左对齐，不用两端强制拉伸制造字缝。
- 图片、表格和附注留在所属范围，表格用`.table-wrap`局部滚动；页面本身不能出现遮挡正文的横向滚动。
- 所有必要资源用相对路径，与HTML一同放在可移动目录内；不引远程运行库、绝对本机路径或base64资源。
  默认模板没有额外资源，不拷贝未使用的图表库或字体包；新增第三方资源保留对应许可。
- 打印隐藏无用导航，保持完整正文，不给整篇设置`break-inside:avoid`导致空页；展开读者需要打印的说明。

## 生成与正文核对

便捷生成器接受**已经确定的纯文本稿**，不是Markdown解析器：首行题名，空一行，随后是正文；
用空行分段，段内换行与空格原样保留。将转换结果登记为送审文本，不能审读后去掉Markdown符号却沿用旧摘要。
便捷生成器不擅自补题、改字或重新分段。多版本各有自己的文本、人物基准与审读状态。

```bash
python3 <writer-pen>/scripts/render_html.py --text 稿件.txt --output output/作品/作品.html --lang zh-CN
python3 <writer-pen>/scripts/validate_html_output.py output/作品/作品.html --text 稿件.txt --expected-language zh-CN
```

多版本重复`--text`，并提供集合名：

```bash
python3 <writer-pen>/scripts/render_html.py --text A.txt --text B.txt --text C.txt --collection-title "三种写法" --output output/作品/作品.html
```

集合名是导航标题，不取代各篇文学题名。生成器拒绝覆盖已有文件；要更新现有文档，按授权窄改，
保留净稿区的`data-writer-work`、`data-writer-title`与`data-writer-body`标记，再用对应原始净文本重新核对。
复杂改稿实录可直接基于模板写HTML；不能为让脚本通过擅自加题或改稿。
用户明确不要题名时，输入文件仅含正文，生成和核对两个命令都加`--untitled`；网页标签页有通用名称，页面不新增可见题名。

检查器校验内部跳转、资源路径、语言声明，以及与各稿**题名、字词、顺序和分段**的一致性。
`static-checks-passed`只是静态结果，不代表文学审读、页面布局或读者体验通过。不能把源码存在当作内容可见。

## 与已有写作审读衔接

保留当前literary流程、人物封存及两名审读者，不导入Reader's Seat的functional流程。
原生候选仍用含题名的纯文本稿；HTML作为与它逐字对应的实际呈现件单独绑定。
可以在送审前检查页面，也可以先完成内容审读、再登记呈现；最终交付前两者都须核对：

1. 写前plan的`format`设为`html`。原生正文继续按 [执行说明](execution.md) 登记，不能用HTML标签代替文学文本去计算字数。
2. 正文稳定后生成HTML，运行逐稿核对，实际检查页面；把HTML文件、静态核对结果、实际截图与版面记录
   一并放入当前`assessment.layout.evidence_files`。layout注明target、viewport、findings及真实reason。
   另填`reading_observation: {quote, observation, status}`，用当前短引定位实际页面的分段、段间距与停顿观感；
   不能只写“无溢出”。`status=fit`才支持受检交付；`needs-revision`先修呈现，不新增文学审稿轮次。
   这些是私有工作证据，留在`.work`等工作目录，不随作品公开。页面引入资源时也将资源纳入记录。
3. 以原纯文本执行candidate与两名独立审读。生命周期保存HTML、资源与页面证据的不可覆盖快照。
   正文、题名或分段改变须重新登记与审读；只改版式则使用下节的呈现更新，不自动消耗文学审读轮次。
   若此时尚未制作页面，候选layout如实记录unmeasured及原因；内容审读之后通过presentation提交真实呈现检查。
   在呈现核验完成前，原生check和最终HTML核对仍不能宣称完整交付通过。
4. 原生`writing_run.py check`通过后，对实际HTML执行带记录的最终核对：

```bash
python3 <writer-pen>/scripts/validate_html_output.py output/作品/作品.html --text 稿件.txt --run RUN --lifecycle-run LIFE
```

多版本按同样顺序重复`--text`、`--run`和`--lifecycle-run`，每篇必须对应自己的当前稿和记录，
全部绑定同一最终HTML。不能只检查其中一篇就声称合集完成。
`record-bound-html-checks-passed`还要求原生检查通过、文本为当前稿、HTML已在当前版面证据中封存；
它不证明审美共识、真实通读或人类共鸣，也不授权发布。没有全套记录的简单排版任务只报告实际检查范围。

审读未完成时不能借转成HTML冒充完成。按原草稿规则处理，在正文之外显著标注真实限制；
可用`--draft-notice`携带说明，但该参数不提供审读豁免。不要把过程文件、私有链接或本机路径嵌进成品。

## 审读后的呈现更新

正文、题名和分段均未改变时，可以重新检查边距、配色等呈现，不重跑文学审稿。
先在真实浏览器核对新页面，再通过统一入口的presentation命令提交新记录：

```json
{
  "html": "/本任务/output/作品.html",
  "status": "inspected",
  "reason": "这次呈现修改及实际检查范围",
  "target": "实际页面",
  "viewport": "实际检查的视口与打印范围",
  "findings": "实际结果与未解决问题",
  "reading_observation": {"quote": "当前正文中的精确短引", "observation": "此处在实际页面上的段落层次、间距及阅读停顿", "status": "fit"},
  "evidence_files": ["/本任务/output/作品.html", "/本任务/检查结果.json", "/本任务/截图.png"],
  "reading_effect": "unchanged",
  "reading_reason": "为何没有改变内容可见性、顺序或文学停顿"
}
```

reading_effect可以为unchanged、changed或uncertain。后两者阻止沿用旧文学审读，须重新登记候选并受原三轮限制。
程序逐字核对题名、正文与分段，绑定新页面和实际资源的摘要；它不能证明作者对阅读影响的判断正确。
新记录保留旧证据快照，不改写原审稿返回。未补新页面证据的样式或资源变更仍会阻塞最终核对。

## 真正打开页面检查

交付前打开最终文件，至少检查约1440px桌面、390px手机和打印模式：

- 从标题读到结尾，确认全部正文可见，无遮挡、裁切、丢字、乱码或错分段；多版本不遗漏。
- 原有段落与换行不被版式拆碎；长标题、长链接及多行附注均留在边界内。
- 本地资源实际加载，没有意外网络依赖；禁用JavaScript时仍能读完整作品。
- 点击实际目录锚点，检查键盘焦点、折叠说明和其他新增交互，不只看截图。
- 打印能得到完整作品，页间没有大面积无故空白；不能把屏幕截图称为已检查打印。

使用现有浏览器/Playwright能力，保留实际结果；缺少浏览器时如实交付“尚未核对显示”的草稿，
不能静默降为聊天全文或宣称页面已验证。仅格式生成不需要新建服务器。
交付本地HTML链接，适合时在应用中打开；有配套资源则交付整个目录。未经授权不上传妙搭或其他网站。

有可用Node与Playwright时可直接运行本包浏览器检查，`NODE_PATH`指向宿主实际提供的模块目录，不下载或硬编码本机路径：

```bash
node <writer-pen>/scripts/check_html_render.cjs --html output/作品/作品.html --out .work/本轮页面检查
```

它实际打开桌面、手机、禁用JS和打印页面，检查正文可见性、溢出、锚点、基本键盘访问及资源，输出截图、PDF与结果。
若Playwright未安装配套浏览器而本机已有Chrome，可加`--channel chrome`，使用临时独立浏览器上下文，不读取用户日常会话。
还须查看截图，确认文字密度、留白和关系清楚；静态源码与模型自报不能代替实际浏览器结果。
自定义控件或复杂改稿视图另测真实交互；本检查不宣称覆盖一切控件或完成WCAG全量审计。
