# 改稿：让改动服务于作品

## 先读到能判断

读用户给出的完整稿件或必要相邻段落，再决定问题是什么。
用户只提供片段时，评价限于片段；不能把没读到的后文当作不存在。
识别叙述者、节奏、词汇、对话习惯及有意重复，理解作品想让读者进入什么处境。
原稿的声音是一项材料，不是不可触动的标准；判断它是否适合人物和此次改稿目标。
诊断请求只给诊断，不未经请求另写全篇；用户要求改稿则直接完成相应幅度的修改。

用户要求“基于原文重新写”时，重新读取原始材料并选择人物、结构和细节，不把上一版
新增的情节或删减决定当成已定设定。遵守当前有效的修改权限与限制；用户要求不拘泥于
历史意见时，将旧意见视为待重新判断的建议，而不是逐条照办或逐条反着改。
从原文出发可以重新得到相同的有效改法，不因某种写法曾在旧稿出现就排除；有必要时可将
已知有效写法作为候选，仍须在本轮上下文检验，不直接接续旧稿。改稿痕迹始终以指定原文为底稿。

## 按请求决定修改范围

只改或评价标题时，转到 [文学标题](titles.md)，阅读已有正文但不改动正文、不重建人物封存。
全篇改稿动笔前默认先定工作标题，原题可直接沿用；无题时根据已读素材与本版方向暂拟，不等用户另提请求。
成稿后复核它与当前作品是否仍合适；替换要比较原题与候选的得失，不因正文重写就必然改题。
用户指定保留题名、仅改某段或明确不要标题时，不擅自扩展到全篇改题。“只要正文”不自动取消标题。

一般的“改一下这篇作品”“把它改好”按文学改稿处理，不自动降为轻度润色。
可改词句、合并叙述、移动铺垫、重排段落、删减无效部分，不必逐项求批准。
可以为故事与人物增删事件、重塑声音、调整视角和结局，选一个成立的方向直接完成。
原素材是创作材料，不是每项都必须保留的清单。用户明确指定的设定、保留内容和局部修改范围照办。
按 [素材取舍](narrative-development.md#把素材变成作品而不是逐句兑现) 复核材料中的概括在本文是否成立；
心理发展不足时改关系与经历，不能只把结果换一种说法，也不必为保住原句不断补前提。
材料存在矛盾时，可以选择或重建一条自洽时间线，并核对前后情节。

## 不只改错，也试出更好的组织

先判断主要收益在语言、段落、叙述还是人物情节。需要改结构时先改结构；
整体已经成立时，也要检查句段能否更有表现力，不等到“读不懂”才动笔。
遇到有潜力的段落，真正写出候选改法，放回上下文比较，再决定采用、调整或恢复。
这是一种编辑动作，不要求向用户展示内部尝试，也不要求每段生成多个版本。

候选应努力实现同一创作目标，而不是只把原句截短、削去人物口气后让原文轻易胜出。
发现候选明显损失原有长处，先尝试兼顾改善与长处的写法，再决定是否放弃改动；
例如保留人物的嘴硬或迟疑，同时重排拖沓语序。候选不佳只能证明这次试改不佳，
不能据此宣布原文已无改善空间。无需无限试写，也不预设必须有一版胜过原文。

核心场景反复修句仍不成立时，参考 [叙述选择与场景发展](narrative-development.md)：
检查讲述时点与距离，必要时试换叙述位置；辨认是缺少场景经验，还是已有细节互不承接。
既可以删去无效部分，也可以展开被过早概括的体验，不默认越改越短。
按 [版本比较与取舍](revision-evaluation.md) 比较候选和基准的相关作用；改开头尤其不能只评新稿。
以具体阅读收益决定采用，不以是否跨越评分档位决定是否动笔。用户指定恢复或更换时
按其要求处理，不用分数覆盖指令。

| 观察到什么 | 可以实际怎样改 | 比较什么 |
|---|---|---|
| 同一状态先介绍、随后再描写一遍 | 合并交代，把对象、动作、时长放进同一句或相接的动作中 | 是否更集中，是否丢掉必要的发现过程或反差 |
| 时间、地点、人物零散排列，读起来像材料清单 | 重排为场景；按行动、感知或叙述目的安排出现顺序 | 读者是否更早进入场景，而不是一律改成时间顺序 |
| 细节已经表达情绪，后面又解释一次；段尾漂亮但分散注意 | 试删整个解释、比喻或总结，让段落提前结束 | 停在哪件事上更有力量；删去的内容是否支撑后文 |
| 动作绕、主语游移、名词和修饰替动作说话 | 换动词、改主被动、补必要对象，重写句子而不只换标点 | 动作是否可见，施受关系和人物主动性是否符合新版本 |
| 每句都想俏皮、抒情或像金句 | 删去一层机锋，换成符合人物的直接表达，或把它移到真正重要的位置 | 是否让人物压过句子的聪明；不把幽默一律磨掉 |
| 文句通顺，但人物反应、冲突或转折没有展开 | 在虚构权限内增删动作、对话和事件，重新铺设动机、阻力与后果 | 人物为何这样选择，新增内容是否真正改变关系或推进故事 |
| 开头进不去、场景散、结尾没有兑现前文 | 重选进入点、压缩过渡、移动揭示、重写结尾并回修铺垫 | 整体阅读是否改善；不是每篇都要反转或顿悟 |

句末和段末是注意力的落点，值得主动调整。词语也不只是同义替换：
看它是否属于这个人物的口吻、是否准确、是否让读者先看见重要对象。
没有现场对话，也可以对一个不在场的“你”说话；检查的是叙述关系和语气是否成立，
不是机械禁止自言自语中的第二人称。人物口吻可以调整，但应在全篇维持相应关系。

## 从人物与故事需要出发的改稿流程

以下是判断顺序，可按任务范围往返，不要求逐项向用户汇报：
允许本地记录的实质改稿从 [统一入口](workflow.md) 开始，保存版本与审读；具体问题按 [操作方法](operations.md) 触发执行。

1. **明确目标与边界。** 读指定底稿，确认本次要改善的效果和有效的创作权限，识别原文已有的长处。
   区分明确约束、可修复的问题和可商量的审美偏好；不要先定改法，再改目标为它找理由。
2. **分析人物，封存理解。** 按 [人物先行](character-first.md)，用原文的行为、台词和反例建立主要人物理解，
   区分已知内容、暂时解释与拟虚构设定；确认其欲望、顾虑、关系处境和矛盾如何影响选择。
   用五层分析覆盖相关背景、内在倾向、关系、当下与文学呈现，在开始改写正文前封存本轮记录。
   找出已有力量及尚未充分表现的地方，不从身份标签编习惯，也不先决定要删多少或增加几个事件。
   区分“保住什么作用”与“是否沿用原写法”：关键情节可保留而句段重写；
   找出人物经历、关系变化或选择后果中尚未展开、且值得发展的部分，具体方法见
   [叙述选择与场景发展](narrative-development.md)。已允许虚构时，原事件也可替换，
   不把原情节自洽等同于已充分展开，也不把原文没有的内容一律视为缺口。
   在动笔前确定本版工作标题，可沿用原题；有明确题名限制时遵守，不让题名反过来强迫人物或情节。
3. **在合适层级试写。** 并列考虑保留、删减、换词、调序、合并、展开和虚构，选择能解决具体问题的方式。
   只改一个动词足够就不加事件；存在发展需要时，实际试写现有场景的重构或新的经历，
   不用几处润色、补接问答代替，也不因之前虚构失败就默认退回修句。原文和候选都按实际效果判断。
4. **先读净稿，再定位问题。** 暂时放开改稿说明，连读候选，先看整篇留下什么，再按需要追查具体原因。
   从正文概括人物后读取封存分析，记录正文依据与差异；合理发展另存修订，不能倒改基准消除偏离。
   同步复核工作标题：读前期待、全文联系、声音和读后意味是否相合，明确保留或进入改题比较。
   这仍是自查，不冒充独立读者测试。局部任务只读必要上下文，不声称审过未提供的全篇。
5. **比较得失，决定取舍。** 小改在必要上下文比较，关键删改比较完整场景及后果，开头要与原开头对照。
   选择有具体收益且代价合理的版本，不要求每个维度都提升；不能拿弱候选证明原文最好。
   原文有效而候选收益不清时可以保留；两版都有问题时修复、另试或说明尚未解决的限制。
   默认记录关键文字依据与取舍，用户明确要求时才附诊断分数，同分可改，高分也不自动胜出。
6. **回修联系，再读成稿。** 按 [场景与行动](narrative-development.md#场景与行动从人物接续不从结果拼接) 复核前提、时空、人物认知、行动与物件状态，以及后续话语和反应；实质修改后重新连读净稿，检查局部改善是否破坏整体。
   有新的问题就回到对应环节；当前目标已实现且没有未处理的关键问题或有根据的新改法时停止，
   不为凑修改数量或提高分数继续改。

看见“也、又、因为、就、似乎、大约”等先判断作用，不执行删除清单。
重复可能是人物口吻、强调、音乐性或回环。省略可能是故意的含混，也可能真让关系断裂。
长短句、形容词和被动句只提供问题线索，不凭数量判好坏。

## 哪些变化需要特别留意

- 数量、时长、程度、频率、不确定性，以及人物有没有真的做过某事。
- “就”与“竟”这类词携带的预期和心理解释；“他说”这类词携带的消息归属。
- 表达变得精巧之后，是否失去了叙述者的年龄、口语、粗粝或局促感。
- 削减背景之后，是否丢了后文理解所需的条件。
- 补足动作之后，是否新增了原稿没有的姿势、动机或事件。

这些是需要意识到的变化，不是所有文学改稿都不得触碰的清单。
可主动设计这些变化，并核对它们对全文的影响。
人物必须可信不等于必须懂事；不要自动把嫉妒、狼狈、粗鲁改成体面和解。

## 改后通读，不让批注替正文成立

按 [净稿通读](read-through.md) 检查完整改后稿，不从“我设计这个动作是为了表现什么”
倒推人物一定会这样做。批注里说得通，不能补偿正文里没有写出的动机或背景。
允许虚构时也需审核新增内容的必要性；让整篇更可信可能要撤回新写的情节，而不是再补几条解释。

同时检查是否只做了表面修饰，遗留可处理的组织和人物问题。不能用大量保留批注替代深改，
也不能用大量新增动作证明深改。处理问题后再读净稿；不设删改比例，不声称能靠检查表保证文学质量。

## 交付方式

通常给一个修改稿，再用少量说明解释关键取舍。只要正文就不附说明。
保留与修改都是编辑选择，要有上下文理由；无需每次给多个版本。
用户要对照或学习时，引用必要原句，说明“问题—改法—收益或代价”；
用户要诊断时，指出有分量的问题，并承认片段之外的信息可能改变判断。
用户要带痕迹改稿时，记录实际删除、增加、替换、移动与重构；按需给净稿，
并让净稿与痕迹逐项一致。虚构新增或人物、结局的大改可在旁注说明创作目的，
不标成原事实纠错，不伪造“试过又撤回”的修改历史。
不自动附加“发送前提醒”、业务结论或行动项。默认以文字依据说明关键取舍，
用户要求评分时才附相关分项诊断，不给作者打文学水平总分，也不以评分代替比较。
