# Unified literary workflow

Use `python3 scripts/writer.py COMMAND TASK ...` for substantial writing that
allows local records. The wrapper sequences existing checks; it does not write
prose, judge literary quality, call models, publish, or overwrite a manuscript.
Light diagnosis and title-only work retain their existing lighter workflow.

## Start once, before units

```bash
python3 scripts/writer.py start TASK --request request.json --task-id STABLE_ID
# Add --registry PATH only for the host's configured persistent task registry.
```

The request contains the native `contract` and literary `plan` objects described
in [execution](execution.md) and [quality records](writing-quality-records.md).
New literary plans separate `writing_basis.given`, `interpretations` and `choices`
inside that existing plan. Keep provisional explanations and stylistic choices
out of user constraints; the wrapper checks the separation, not its truth.
For material-based work, record consequential handling in the same `choices`
list; do not treat every supplied phrase or conclusion as a required outcome.
Before the first checkpoint, the plan records `working_title: {text, reason}`.
Use the provisional, retained or user-fixed title; an explicit untitled request
uses `text: null` and its real reason. The frozen plan establishes registration
order, not the actual time an idea was conceived. Do not invent a title history.
`plan.purpose` must match `contract.goal`, `plan.scope` must match
`contract.scope`, and their explicit constraints must agree. Fiction permission
is not broadened. Keep the user's exact restrictions, character requirements,
preserved text, edit span, authority and source gaps.

Optional `source: "path"` or `sources: ["designated.txt", "notes.txt"]` is resolved
relative to request.json. With multiple sources, the first is the native
designated manuscript; all are available to the source-aware professional role.
Do not concatenate independent sources or guess which is authoritative.
For `contract.mode=revise`, declare `source_title` as the designated source's
actual title or null when untitled. `opening_text` must include body opening
text after a declared title; a title match alone is not an unchanged opening.
Do not infer a title just because an untitled opening is a short paragraph.

Start captures immutable local input snapshots and a runtime bundle, then
initializes literary lifecycle, native writing records, and managed task identity
before any units. `TASK/workflow.json` is the sole path map, not a second status
or round ledger. Later commands verify the bundle and run its pinned scripts,
even after the canonical package changes. Do not edit a task's pinned runtime,
rehash old acceptance, or install this staged package as part of writing.
Legacy runs are not automatically pinned or migrated. Resume them with their
original runtime and registry; a new map is not permission to reuse old acceptance.

Repeat the identical start command after a partial initialization. Complete
components are retained; missing components may be initialized. An ambiguous
partial directory or pin without workflow.json is reported as incomplete, never
deleted or silently adopted. Preserve it and the registry for explicit recovery.
Do not change the task ID, registry, or directory to reset the three-round limit.

## Prepare, draft, and self-check

```bash
python3 scripts/writer.py prepare TASK --character people.md --id people-v1 --reason "Writing-time interpretation"
python3 scripts/writer.py draft TASK --id v1 --file manuscript.txt --record unit.json
python3 scripts/writer.py self-review TASK --clean clean.json --comparison comparison.json
python3 scripts/writer.py decide TASK --file decision.json
```

`prepare` seals actual notes before draft registration. Alternatively pass an
existing sealed character manifest with `--record`; omit it only for the native
contract's explicit exemption. Develop an interpretation under a new character
record ID; never rewrite the baseline. Timing declarations must be truthful.

Before composing the first prose draft, choose a working literary title using
[titles](titles.md). An existing or user-fixed title may serve; an explicit
untitled request takes precedence. After composing and clean-reading the whole
work, review whether to retain or change that title. Keep a short decision in the
existing notes/comparison records (`kind=other` when applicable). Register and review the chosen title together with the current prose;
the wrapper binds text versions but does not prove when a title was conceived.

The single full-manuscript checkpoint above is available only when the plan has
one reading unit. `unit.json` supplies the planned `unit_id`, a summary, and actual
`observations: [{quote, reason}]`. No observation is generated by the wrapper.
For several units use `--units units.json` instead of `--record`; its JSON array
contains `{text: "scene.txt", record: "scene.unit.json"}` for every planned unit,
with paths relative to units.json. These must cover the entire manuscript at
candidate registration. The title belongs to the reviewed text when present.

Self-check and decision inputs use the unchanged native formats in
[execution](execution.md). Clean reading precedes comparison, including character
and source comparisons when required. The wrapper cannot close a constraint or
coherence issue by relabeling it a preference.
Clean observations now add `covers: [check IDs]`; their union covers the shared
[review families](review-coverage.md). One substantive observation may cover
related families, without seven repeated narratives. A generic full-coverage
flag is not a substitute. Comparison records still cite original/current text.

## Assess, then request actual reviews

```bash
python3 scripts/writer.py candidate TASK
# Read the returned measurement report; fill its empty assessment template.
python3 scripts/writer.py candidate TASK --assessment assessment.json
```

The first call stops with `assessment-required`; it starts no review. Supply
actual contextual observations, applicability decisions and every signal's
disposition. Counts are prompts for judgment, not scores or rewrite quotas.
`--report PATH` chooses a new report path and `--geometry PATH` supplies actual
geometry when needed; neither bypasses reproducibility or layout requirements.

Once the assessment validates, candidate registration and review-start return
the exact professional/reader packets and `host_bridge` instructions. Load the
returned `writing_host.js` and call `runWritingHost(tools, options)` with the
returned options in the real host. It performs actual isolated calls and captures
untouched returns. The wrapper itself calls no model. Missing host capabilities,
malformed returns and uncertain launches are technical blocks, not passing
reviews or new semantic rounds. Resume the same bridge; follow
[managed execution recovery](writing-execution.md) for launch uncertainty and
bounded technical retries. Do not launch a duplicate reviewer or fabricate a
receipt. Reader packets exclude author intentions and other reviewers' opinions.

```bash
python3 scripts/writer.py finish-review TASK
```

This imports exact captured role returns using the native functions. Optional
`--results PATH` supplies the bridge's JSON role-to-result-path map; it must match
the capture store exactly. Manually written role records are not a substitute.

If returns contain unresolved author choices, `pending-editorial` keeps the same
batch open and returns their exact bindings. Write a separate choice file:

```json
{
  "draft_id": "draft:v1",
  "role": "reader",
  "finding_id": "the-returned-finding-id",
  "reviewer_receipt": {"path": "the-returned-path", "sha256": "the-returned-hash"},
  "choice": "retain",
  "reason": "The author's actual text-supported reason",
  "trial": {"current": "Exact current passage including the finding quote", "alternative": "Actually tried alternative passage", "gain": "Concrete reading gain", "loss": "Concrete reading loss", "attention_cost": "Attention or pacing tradeoff"},
  "evidence": [{"artifact": "draft:v1", "quote": "Exact current manuscript text"}]
}
```

```bash
python3 scripts/writer.py author-choice TASK --file choice.json
python3 scripts/writer.py finish-review TASK
```

`retain` can resolve a supported artistic choice, never a legacy blocking issue.
It needs actual trial passages and their costs, not a purpose attributed to the
detail. The reader's separate understanding/experience return is required even
when the reading was indifferent; it is not a requirement to praise the work.
Explicit `revise` or `defer` closes this same batch as fail so work can continue
under the remaining budget; missing choices do not close it. Suggestions are
optional and never block. The aggregate is native-computed, not a supplied PASS.
Unresolved independent blocker/editorial findings remain attached across draft
versions until explicitly resolved on the current draft. Changing the title,
text or paragraphing does not erase the earlier question. Keep the original
receipt and finding ID; do not edit old reviewer returns to close it.
Review retries do not replace or edit an earlier aggregate. If it is already
bound to different choices, stop for explicit recovery rather than overwrite it.

## Inspect and deliver through the checked exit

```bash
python3 scripts/writer.py status TASK
python3 scripts/writer.py check TASK
python3 scripts/writer.py deliver TASK --to new-manuscript.txt
```

Status reports an actionable next step, never acceptance from record existence.
Check and deliver route the existing managed native exit: current text, sources,
self-checks, decisions, lifecycle and original capture evidence must agree.
After three completed rounds with a current failing review, explicit
`deliver --draft --to new-draft.txt` is available only when native guards allow it;
retain its notice, explain unresolved issues outside the work, and ask for the
author's next direction. No fourth round or silent downgrade is created.

For HTML, keep the reviewed manuscript as the semantic candidate. After actual
browser inspection use `presentation TASK --record layout.json`. Its record has
`html`, `status: "inspected"`, `reason`, `target`, `viewport`, `findings`,
`reading_observation: {quote, observation, status: "fit"}` about the actual rendered
paragraph hierarchy, spacing and reading rhythm (not just missing/overflow checks),
`evidence_files: [html, browser_evidence]`, `reading_effect` (unchanged, changed,
or uncertain), and `reading_reason`. This calls the existing presentation API;
it does not consume another semantic round. Changed or uncertain reading effects
cannot reuse literary acceptance: register a new draft version at a new path,
self-check and decide it, then assess and review it within the remaining budget.
Finish with the pinned
`validate_html_output.py` and the complete checks in [HTML output](html-output.md),
including exact prose, paragraph and desktop/mobile/print evidence. Text export
alone does not verify an HTML deliverable. No command authorizes publication.

These records check a cooperating local process and exact bytes, not actual
generation chronology, independent identity, human response, or literary merit.
Synthetic tests verify plumbing only; they are never actual review evidence.
