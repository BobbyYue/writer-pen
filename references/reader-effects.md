# 阅读效果：把判断落到文字与读者反馈

适用于写前选材、同轮审读与局部改稿；不另建审稿小组，不增加三轮预算。
轻量任务直接应用判断；完整文学作品沿用现有写作记录。创意文案和纪实特写复用方法，不套小说的记录流程。

## 写前分清两种目标

在现有 `literary_intent`、`writing_basis` 或文案构思中说明希望读者多看见什么：
必要事实关系要能恢复，人物意义、立场和感受可以开放。不要列唯一寓意或要求读者同情某人。
从材料选择有表现力的关系与细节，不为“深刻”硬造社会批判、复杂人物、反转或象征。
这些意图只供作者和专业审稿对照，不发给独立读者。

## 同一轮检查怎样取证

先让读者自由回读，再核对材料和意图，避免用“你是否看出了他的身份矛盾”暗示答案。
可问：“这个人的处境有什么特点？哪些文字让你这样理解？哪里仍不能确定？”

| 要检查的效果 | 本文中的证据 | 使用现有检查 |
| --- | --- | --- |
| 观察是否具体 | 读者能指出具体处境或关系，而非只给“善良、努力”等标签；没有人物的作品按其对象判断 | motivation_action、language_detail |
| 细节是否值得保留 | 对可疑处试删、换写或移位，比较理解、情绪、声音与节奏的得失；必要过渡不强求新信息 | language_detail、revision_effects |
| 行动是否可信 | 读者能从前文解释行动，还是必须补出关键动机；误判与冲动可以成立 | motivation_action、scene_continuity |
| 含蓄是否有效 | 区分正文事实、合理推断、仍有疑问；解释不同与前提缺失分别处理 | narrator_knowledge、title_opening_ending |
| 修饰是否有作用 | 删除后是否损失时序、精度、人物口吻、反差或节奏；不按词性定好坏 | language_detail、paragraph_rhythm |
| 整体留下什么 | 分别记录理解、注意力变化与留下的内容，可以读懂但不喜欢或不在意 | reading_response、title_opening_ending |

独立读者在原有 `understanding` 中增加 `readings`，只记影响判断的读法，不逐句标注：

```json
{"observation":"我读到的处境与变化","quote":"当前正文短引","readings":[{"kind":"inference","claim":"从这些动作形成的理解","quote":"支持或引发这个读法的当前正文短引"}]}
```

`explicit` 是正文明确写出，`inference` 是读者推断，`uncertain` 是尚不能确定；不要求三类都出现。
引文与分项完整性由程序核对，推断是否充分仍须结合上下文判断。作者先核对读者依据，不能把所有不符合自己意图的读法判错。
有理解缺口就改承担该联系的段落；有文本依据的不同解读保留；仅有偏好差异可取舍。存疑保留时沿用实际两版比较，不加统一解释段。

## 按需使用等级，不合成文学总分

默认文字判断。用户明确要求量化诊断时，在相关 `development_response.checks` 中附 `support_level`，复用原有引文与 observation 说明理由。

| 等级 | 判断依据 | 行动 |
| --- | --- | --- |
| 0 | 存在明确阅读断裂：关键联系缺失或前后冲突，需凭空补出才成立 | 指出断裂及影响，按原有 blocker/editorial 分类处理 |
| 1 | 有依据但联系仍薄，或需要在两种写法间取舍 | 尝试局部改法，比较收益与损失 |
| 2 | 当前依据足以形成合理理解，表达与作用相称 | 可以保留；不意味着满分或不能更好 |
| null | 本项关系在此任务中不存在 | 说明不适用，不填0，不计入统计 |

未读、资料不足和未测不是0或null；先如实报告范围，不提供该项等级。
等级有序但间距未知，不相加、平均或换算百分制。数字不决定交付、角色 verdict 或是否重写；仍以实际问题和取舍记录为准。
不要以细节多、人物矛盾多、情绪强烈、误读少或修改字数多推定文学价值高。

## 有实际反馈时怎样统计

只有实际采集了反馈才运行 `python3 scripts/reader_study.py feedback.json --text current.txt`。
输入固定同一文本摘要、同一问题集和评价口径；真人与模型反馈分别列示。按读者ID去重，未答和不能判定均保留，不能删掉后提高比例。
问题分 `fact`（必要事实关系，结果 correct/incorrect/uncertain）与 `interpretation`（开放解读是否有文内依据，结果 supported/unsupported/uncertain）。不能要求开放解读与作者意图一致。
判断由评阅者依据原答、原文和事先定义的口径给出，程序只验绑定并算数，不自评“正确”。输入格式见脚本 `--help`；现有独立回读可作为模型材料，不能伪装真人反馈。

- 理解结果：正确人数 / 该组收到反馈的人数；同时给出 incorrect、uncertain、missing 数量。
- 解读依据：有文本支撑的人数 / 该组收到反馈的人数；不同但有依据的解释都可计入。
- 没有某组反馈：分母0、比例null，记未测。单个模型回读不证明真人理解率或共鸣。
- 对比修前修后：固定任务、问题、评价口径及读者条件，隐藏版本身份、变换顺序，保留持平、各有得失与新引入的问题；不同正文另存记录，不混算。
- 阅读中断、记忆或情绪变化可保留原答，但没有实际行为或延迟回忆实验，不把模型自述换算成读完率、记忆率或情绪强度。

不要求每次作品招募多人或做实验；这些统计服务实际反馈与长期校准，不是新的发布门槛。

## 例子用于校准，不用于仿写

《孔乙己》“站着喝酒而穿长衫”可以支持人物处境的不同理解；“他过去一定很富有”则需要额外证据。
掌柜听说孔乙己被打断腿后“仍然慢慢的算他的帐”，“慢慢”参与构成动作与遭遇的反差，不是见副词就删。
结尾“大约”与“的确”的张力可以结合叙述者所知与长期缺席理解，不据此推广为任意矛盾都成立。
这些是文本细读示例，非统一正确答案、固定句式或审美量表。[鲁迅《孔乙己》原文](https://zh.wikisource.org/wiki/孔乙己)

程序合成测试只证明记录与计算约束；独立试读记录具体输入上的行为，真人测试另列。三者不能互相冒充。
