# 已知限制

## 审读格式可能阻止完成

v2.5.4 同步创意文案及人物视角等方法更新；程序实现未变化，以下格式问题与原案例验收状态继续保留。

v2.4.1 仅同步写作指令与作品内容的边界检查，不修复以下问题，也不改变原案例的验收状态。

v2.4.0 的《周一见》案例中，专业审稿已经给出实质判断，但两次返回没有通过格式核验：

1. 一次局部试改位于两条检查引文之间，试改原文未包含任何一条所列引文。
2. 对同一底稿的两处引用重复使用相同来源编号，程序要求该列表的编号唯一。

本版不会把这类无效返回记作成功。技术重试最多两次，与最多三轮的文学修改分开计数；用尽后保留当前作品和原始记录，说明尚未完成的检查，不开新任务清零，也不手工修改旧返回。

这说明本版仍有实际运行上的格式摩擦。程序回归通过不等于端到端创作已验证成功；本仓库案例也不作该承诺。

## 调用和校验的边界

- 独立审读需要真实宿主调用与原始返回采集；文本中写“已审读”不能替代它。
- 新上下文隔离会话历史，不等于文件系统隔离；宿主仍须限制审稿者使用的材料。
- 脚本可以约束通过规定入口登记和交付的流程，不能阻止宿主绕过它直接回答。
- 引文存在、摘要一致或角色不同，不能证明文学判断正确，也不能证明真实读者投入。
- 实际模型生成、记录校验、页面显示与人类阅读效果是不同层次，须分别报告。

## 复现与反馈

遇到问题时保留同一任务的原始输入和返回，不编辑已封存文件。公开反馈只提供脱敏的错误类别、版本和可复现的虚构材料，不上传真实私稿、账号信息或内部链接。
